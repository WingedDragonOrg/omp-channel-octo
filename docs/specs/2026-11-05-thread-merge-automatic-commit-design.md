# 子区合并前的原生提交

日期：2026-11-05
修订日期：2026-11-06

## 目标和范围

owner 在支持合并的单项目子区执行 `/thread merge` 时，先通过 OMP 原生 `commit` 处理工作树改动，再执行既有 Worktrunk 默认合并。相对目标分支是否有新提交不影响触发。无未提交改动时沿用既有合并路径。直接调用 `octo_management thread-merge` 的接口和语义不变；shared 多项目仍拒绝，ready fork 仍只归档。

## 触发和授权

通过既有权限及工作区资格验证后，检测当前工作树中已暂存、未暂存和未被 Git 忽略的未跟踪改动。有任一改动则调用与 `/commit` 相同的 OMP 原生提交路径。owner 授权 OMP 现有提交策略：已有暂存内容时处理暂存内容，否则自动暂存仓库改动；OMP 可能更新 CHANGELOG 或创建多个提交。不得额外提交未授权改动。

提交完成后仅当进程组确认退出、退出码为零、HEAD 确实变化、未被停止或取消，且重新核验工作区身份、绑定、合并计划与工作树干净时，才启动 wt。提交后仍有改动时保留现场并提示 owner；不得让 wt 默认 `--stage all` 将剩余改动另行提交。没有新提交、非零退出、停止、取消、结果不明或校验失败均不启动合并，不回滚已发生的 Git 副作用。

## 调度、反馈与恢复

自动提交复用原生 `/commit` 的进度反馈、受管进程/watchdog、停止、状态和结果处理，但不复用其工作树资源排他。它不因其他聊天任务、相关目录/仓库活动或未确认 worker/process ledger 等待或拒绝，也不以等效路径锁替代；独立 `/commit` 仍保留既有资源保护。保持 `/thread merge` 当前聊天与精确 session 顺序及 `/cancel`、`/commit stop`、`/interrupt` 语义，同时避免为自动提交或后续 merge 引入跨聊天资源锁。路径/来源/绑定/计划验证及 shared/fork 限制保持不变。

持久受理与稳定命令身份先于副作用；重复消息不能重复提交或合并。持久记录提交与合并阶段以及实际进程/结果边界，不能把调用已派发或进程已退出误认为业务成功。当前自动提交进程退出/HEAD/后续状态无法可靠确认时，不启动 wt；服务停止或重启后不自动重放、续跑，也不把未知状态报告为成功。保留旧操作的 unknown 记录，但不把旧未确认 worker/operation ledger 当作新 merge/remove 的资源门禁；独立新命令与仍在执行的旧进程可能交错。只有本操作自身取消/停机时等待其受管进程组确认退出；旧未知结果不是运行中证明。停止或取消意图属于整个自动提交合并操作，与合并派发边界可靠裁决：停止先受理时不得启动 wt。任何重启和重复投递均不能绕过成功门槛。

合并仍由既有 wt 默认流程执行：默认 squash 可改写 OMP 生成的提交；rebase、fast-forward 和清理保持原契约。实际合并失败按现有路径交给一次修复任务；成功结果持久化、投递并等待输出排空后归档。进度和结果应能区分提交与合并，提交失败不能声称合并成功。

自动提交和后续合并阶段都没有跨聊天资源排他。工作树干净检查反映检查时的状态；其他并发任务、提交、目录操作或外部进程在检查前后均可能修改工作树/index/ref，OMP 原生提交可能包含或与这些写入冲突，wt 的默认 stage 与 Git/hooks 也可能造成冲突或部分副作用。持久归属/路径校验不能消除检查后的竞态；ref CAS 和 index 锁不构成流水线整体事务或回滚保证。

## 验收

- 临时 Git 仓库与隔离真实 OMP/本地模型、受管进程、wt 夹具证明提交成功发生在合并启动前，目标包含预期内容。
- 覆盖已暂存、未暂存、未跟踪、干净工作树和提交后残留；失败、停止、取消、结果未知、重复投递及重启不得绕过已确认的提交门槛或重复执行副作用。
- 覆盖工作区绑定、持久归属路径或合并计划变化，shared 与 fork；另验证并发聊天任务/相关仓库操作及旧未确认 ledger 不会阻挡自动提交，但身份校验、取消、未知结果不重放、原有合并失败修复、结果投递和归档边界仍正确。
- 执行相关回归、类型检查和生命周期离线基准；验收只使用临时仓库和隔离服务，不操作常驻 bot 或真实仓库。

2026-11-05 隔离验收：真实 OMP 与本地模型、真实 wt 0.80.0 和临时 Git worktree 完成提交后合并；wt 启动时 HEAD 已变化且工作树干净，目标分支包含预期文件。临时仓库 pre-commit hook 失败以及模型请求等待时 `/cancel` 均未启动 wt。专项回归 120 例通过；`bun run typecheck` 通过；全量套件 1801 例通过；graceful/SIGKILL restart 基准的 session overlap 与 duplicate effect 均为零。旧 SQLite 的只读一致性副本迁移后，44 张原表行摘要保持一致，重复打开成功。
