# Loop 事件与子区收尾路由

日期：2026-11-12

## 用户原始需求

1. “目标：绑定的 Loop 任务状态变更为「审查中」不应作为事件被子区感知；已归档或调用过 /thread remove、/thread merge 等结束处理的子区不应被事件重新唤醒，相关事件直接丢弃。范围：调查 Loop 状态变更、事件分发以及子区归档/清理/合并和恢复路径，按现有实际状态定义实现端到端过滤；生成 SDD 后实施。存在会影响其他事件或重新打开子区的产品歧义时，在子区内向 owner 做最少必要澄清。约束：Loop 快照仍须真实推进；不把审查中状态变化转为新任务、steer 或问题答案；不要误丢同次更新中其他符合资格的业务变更；丢弃已结束子区事件必须覆盖入队、竞态与重启恢复，避免后来重放唤醒；保持现有授权、路由和用户主动交互契约。验收：状态变更为审查中不会唤醒任务；归档及 /thread remove、/thread merge 后的子区不因事件被唤醒，事件不会重放；正常活跃子区及其他合格变更按契约处理；覆盖边界与恢复的行为测试、适用的隔离真实链路验收并更新文档。”
2. 修正：“归档/remove 的子区绑定不是直接丢弃事件，而是事件发给 主群聊的 agent 处理”。此项替代第 1 项的直接丢弃要求。
3. 对人工消息使子区重激活后的路由，owner 确认：“继续发往主群，因为子区恢复不代表相关 worktree 恢复了”。
4. 对过滤范围，owner 确认：“全部过滤（推荐）”；未关联子区、按负责人规则送往主群的任务也适用。

## 契约

- 全量快照持续保存服务端真实字段。仅排除状态从其他值转为 `in_review` 这一字段的事件；同次其他业务字段变化仍按原资格规则送达，且不能把被过滤的状态变化表述为事件。升级前已持久化、尚未接受的 pending 输入也按同一规则重新准备。其他状态变化、已有任务的其他业务变化及自动开工规则维持既有行为。
- 已归档子区的绑定及成功收尾的 remove/merge 对应关联继续保留，后续合格 Loop 事件改送该绑定的主群 agent，不受当前负责人变化影响；不送子区、不作为 ask 答案、不额外授权。原子区重新收到人工消息不恢复该关联的自动子区路由。人工对话、显式派发及绑定操作维持原契约。
- 对于已确认归档或收尾的子区，持续保存路由失效事实；由其他来源观察到的服务端已归档状态也纳入。结束处理失败、资格拒绝和未知结果按实际已有 outcome 处理，不能虚报成功。结束处理在途及归档排定与实际投递之间的竞态不能将新事件交到即将结束的子区。
- 快照和派生事件原子提交；待接受事件在最终接受前复核目标与结束状态，并对目标变化重新选择主群。已经进入子区队列但尚未 dispatch 的 Loop 任务在收尾后须转至主群，且跨重启不得重复接受；已派发的工作沿用现有会话和恢复契约，不重放原 prompt。输入、目标与结束事实跨重启持久保存；重启不能把已转交主群的输入重放到子区。未知接受结果保持原有 fail-closed 语义。归档查询失败遵循原有故障路径，不假定子区活跃。
- 结束关联的主群输入须标明原子区与实际目标，让 agent 处理业务变化，不指示其向已结束工作区派发；路由/授权校验和系统输入身份保持既有契约。

服务端只提供当前子区状态；外部归档后、channel 首次观察之前又被人工重新激活的历史，不能从当前状态推断。宿主自己发起的收尾和已经观察到的归档事实则须持久保留。

## 验收

1. `in_review` 单独变化只推进快照；同次标题、描述或负责人等其他变化仍产生一次有效事件，事件无被过滤的状态变化；后续离开审查中的变化按原规则交付。
2. 活跃关联保持原路由；已归档和成功结束的关联在其他合格变化时转交主群，即使负责人改变；主群 agent 与 pending ask 隔离。
3. 覆盖扫描、排队、最终接受与结束操作交错、主群和子区的已有任务、重启及目标改绑；已接受或未知输入不重复投递。人工消息重激活后仍转交主群。
4. 覆盖数据库迁移、隔离 Loop/store/core 测试及真实 CLI/本地协议验收，生命周期变化运行 restart benchmark；不操作常驻服务和真实 Loop 写接口。

## 验证记录

- `bun run typecheck` 通过；Loop 定向测试 7 个文件、117 项通过，覆盖审查中过滤、已结束路由、入队和启动前竞态、恢复及迁移。
- 子区归档、合并、清理、fork、重启和并发定向测试 6 个文件、129 项通过。
- `bun tests/benchmarks/loop.ts` 使用安装版 OMP 和隔离本地模型、Loop 与 Octo 夹具：5 次重启，审查中唤醒 0 次，结束关联事件转主群 1 次，重复输入 0 次。
- `bun tests/benchmarks/restart.ts` 的正常停止和 SIGKILL 两场景均通过；会话重叠和重复副作用均为 0。未操作常驻服务或真实 Loop 写接口。
