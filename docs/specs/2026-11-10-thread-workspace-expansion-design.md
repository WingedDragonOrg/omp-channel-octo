# 已有子区工作区项目追加

日期：2026-11-10

## 用户原始需求

> ## 目标
> 支持已创建的 thread 新增项目 worktree 绑定，包括已有 shared 工作区追加项目，以及已有单项目 worktree 转换为 shared 后追加项目。
>
> ## 范围
> 保留已有工作区、分支和会话；新增项目纳入宿主持久化所有权，供查询和后续清理使用。考虑会话 cwd 迁移及现有资源路径，不以手动创建未登记 worktree 代替受管理绑定。
>
> ## 约束
> 该能力改变工作区与会话契约，先使用 spec-design，结合现有工作区规格与实现形成设计；仅就影响用户承诺的关键决策在子区内向 owner 做最少澄清，并取得设计确认后再实施。保留已有数据和未提交修改，处理创建失败、取消、重启及清理时的真实资源归属；不要操作真实业务工作区作为验收。
>
> ## 验收标准
> 已创建的 shared thread 可追加受管理项目；已有单项目 thread 可转换并追加，原工作、分支和会话得到保留；宿主记录、实际 worktree、查询结果及后续清理一致。覆盖成功、部分失败与恢复边界，使用隔离仓库和适用回归验证。

owner 确认：保留原 worktree 的绝对路径，通过 shared 入口内链接访问；新项目在入口下创建，原会话经原生 `/move` 迁移，确认后实施。

## 契约

- `octo_management thread-workspace-add` 接受 `projects: [{name, repo, base?}]`、指定新分支命名种子的 `worktree_name` 和可选同群目标 `short_id`；复用现有输入、权限、命名和来源校验。工具持久受理后返回 `accepted: true, status: "queued"`，实际结果通过 `thread-info` 查询；该查询展示持久工作区及项目真实身份和状态。
- 已有 ready shared 使用原入口追加；已有 ready single/separate 转为 shared：保留原 worktree 的真实路径、分支与全部内容，在新入口创建指向原路径的链接；链接不构成归属证明，不跟随它清理外部目录。新项目位于入口中。原先工作区及每个新增项目均按实际来源、路径与分支记录；新入口及其父任务目录记录实际归属。
- 存在精确 session 文件时调用原生 `/move` 并验证 session ID、cwd 和迁移后的精确 session 文件；确认 worker 及 ledger 结束后以原绑定 CAS 发布入口。尚未初始化 session 的绑定不伪造会话；已显式换绑的状态必须保持可解释，不覆盖较新绑定。切换工作区记录与绑定的发布必须一致，不得提前宣称 ready。
- 追加与目标子区清理之间必须由持久操作状态和 workspace 版本协调：清理在实际副作用前读取最新归属，存在未结算追加时不清理其资源或入口；追加在清理占用同一归属时不分配或发布。此保护限定本子区的归属变更，不改变 `/thread remove` 与 `/thread merge` 对其他聊天任务、相关目录或旧未知进程的既有并发契约。
- 原项目链接的实际路径和目标须持久记录；清理在确认项目释放后核验链接仍指向所记录的原路径，仅解除该链接，再按各调用方的入口策略清理。链接被替换或状态不明时保留入口和记录并报告。
- 新增操作按目标聊天及精确会话的顺序执行；从目标聊天自身运行任务发起时持久排队，当前任务释放会话后执行，不能同步等待自身。其他独立聊天的普通任务不因路径重叠被串行化。
- 操作 ID、原始 binding 和 workspace、每一步计划、实际确认结果、受管进程身份在副作用前后持久记录；去重不重复创建。创建、取消、失败或停止不回滚原工作；已确认新增资源保持归属，未确认计划保持可追踪且不得按成功报告或盲目清理。重启先确认旧进程退出；未知创建或迁移不自动重放、不猜测成功，禁止任务越过不一致状态。
- 清理依据持久归属核验原路径、Git 来源及分支；分别清理原及新增 worktree，保留现有脏数据/分支保护和 thread-delete 与 `/thread remove` 的不同策略。入口链接不能使外部资源被递归删除；按现有入口清理契约处置链接及入口。shared 继续拒绝 `/thread merge`。

## 验收

1. 隔离真实 Git 仓库中对已有 shared 追加，核对返回、thread-info、数据库与 Git 的路径、分支和归属一致，并成功清理。
2. 含未提交修改的单项目转 shared 后，原路径、分支、内容不变，入口链接可访问，新增项目为真实 worktree，同一 session ID 和历史经真实 OMP 续接；各项目后续按现有规则清理。
3. 覆盖路径/分支冲突、已有任务与顺序、重复调用、部分失败、创建/迁移结果未知、取消、停机与重启；不能丢失已知归属、重复副作用或谎报成功。
4. 使用临时仓库、临时 state/session、有限 localhost 模型与本地 Octo 夹具；运行相关回归、迁移验证和离线重启工作负载，不使用真实业务资源或重启常驻服务。

## 隔离验证

- 扩展、清理、迁移、并发及恢复相关 14 个测试文件：121 pass、0 fail；`bun run typecheck` 通过。
- `bun tests/benchmarks/thread-workspace-expansion.ts` 使用已安装 OMP、本地有限模型与加密 Octo 夹具，完成真实原生工具调用、单项目转换、原会话历史续接和 dirty 工作区保护；模型请求 8 次，持久归属、查询与 Git 状态一致。
- `bun tests/benchmarks/restart.ts` 的 graceful 和 SIGKILL 场景均完成恢复，session overlap、重复副作用和中断通知均为 0。`bun tests/benchmarks/concurrency.ts` 完成 14 个任务，23 个 OMP 进程均确认退出，session overlap 和残留子进程均为 0。
