# Channel 状态接口与 OctoBuddy 浮动面板设计

日期：2026-11-11

## 目标与范围

OctoBuddy Enhancer 在客户端机器上显示浮动状态面板；部署在 `my-mini` 的 `omp-channel-octo` 提供 HTTP 状态快照。客户端通过配置的 HTTP(S) base URL 访问，独立 Bearer token 限制接口访问。面板不干扰聊天，可收起，显示连接状态和最近成功更新时间。

本设计只涉及查询：不提供任务控制、重启、发送消息或读取文件；不发送聊天正文、凭据、原始工具参数或模型输出。实施与隔离验收不修改或重启现有常驻服务；实际部署需另行授权。

## 系统边界

- 状态 API 由 channel 进程拥有，跟随服务生命周期；增强器宿主是 HTTP 客户端，插件只获得明确授权的状态结果。
- 状态来源是运行时活动状态及持久存储的只读查询。现有 `CoreService.status(target)` 在某些分支调用绑定核对并可能写入状态，不能直接作为只读 API；构造独立只读快照，不启动 worker、不核对或修复绑定、不改变数据库。
- `oco status` 当前显示守护进程状态，`channel_control.status` 是 Agent 宿主工具；它们不是外部状态接口。状态 API 不通过聊天发命令或启动 Agent。
- `channelType + channelId` 是聊天身份；bot UID 与目标共同确定状态。接口服务于该 channel 实例的 bot，不接受客户端指定另一 bot。线程使用其真实 channel ID，不回退父群状态。
- 群和子区直接使用页面的聊天 ID；Bot 私聊中页面 ID 是 Bot UID，而 channel 的私聊 ID 是 owner UID。服务快照携带这两个 UID，面板识别出 Bot 私聊时用 owner UID 查询；其他用户的私聊不显示该 Bot 的私聊状态。
- 增强器的状态插件从 OctoBuddy 页面共享实例的 `openChannel` 读取当前聊天身份，每 250 毫秒检查切换；该字段的普通会话赋值不保证触发页面订阅通知。宿主提供只读聊天状态查询。插件在用户信任的个人环境运行，页面提供的目标作为显示依据。插件禁用、页面切换和销毁后取消其请求和定时器，不向旧上下文交付结果。

## 接口与安全

### 网络与配置

- 状态接口随 channel `start`/`run` 默认启用，默认监听 `0.0.0.0:8765`；`OMP_CHANNEL_OCTO_HTTP_ENABLED=false` 显式关闭。默认监听所有 IPv4 接口，部署者按网络选择防火墙和加密方式。缺少 token 时 channel 继续运行，状态接口不启动并明确提示；不会生成 token 文件。
- 服务端配置按字段采用环境变量 > 现有 `statusHttp` 配置 > 默认值：`OMP_CHANNEL_OCTO_HTTP_LISTEN_ADDRESS`、`OMP_CHANNEL_OCTO_HTTP_PORT` 和 `OMP_CHANNEL_OCTO_HTTP_TOKEN_FILE` 分别覆盖监听地址、端口和 token 文件路径。`OMP_CHANNEL_OCTO_HTTP_TOKEN` 有值时直接作为 Bearer token，优先于 token 文件；未设置时，已配置的私有 token 文件可作为回退，未配置则不读取或生成文件。显式配置的 token 文件不存在或权限不安全时报告配置错误。token 为至少 32 字节随机值的十六进制编码，须通过安全方式分别配置到两台机器，不自动跨机器传输。
- 客户端 `OCTOBUDDY_HTTP_BASE_URL` 和 `OCTOBUDDY_HTTP_TOKEN` 按字段优先于现有私有 `status.json` 对应值；未配置 URL 或 token 时仍显示未配置。普通 hostname（例如 `my-mini`）、局域网地址或公网域名由系统网络和 DNS 处理；请求不跟随重定向。
- 启动增强器时，从增强器目录的可信 `.envrc` 取得客户端状态变量，继承的进程环境变量优先；只将状态变量传给增强器宿主，不注入 OctoBuddy 子进程或页面。从 Finder 启动也遵循这一规则。
- 服务端 token 文件由服务账户拥有且仅其可读写；客户端配置文件仅当前用户可读写。创建或加载时检查文件权限，不安全时拒绝启用或连接。token 不进入 URL、DOM、插件消息、日志或错误文字。文件 token 每次请求重新读取，替换后旧 token 失效；环境变量 token 的变更需要重启使用它的进程。
- 每次请求用 `Authorization: Bearer <token>`；缺失或错误 token 返回 401，不包含状态。使用常量时间比较；接口只接受 GET，其他方法拒绝。不得提供 CORS 跨源读取权限；客户端通过增强器宿主发请求。认证不替代网络和主机安全，能读取 token 的本机用户或进程仍可能访问状态。
- Bearer token 本身不提供传输加密。Tailscale 提供其网络链路加密；通过其他网络使用明文 HTTP 会暴露 token 和状态，公网应通过 HTTPS 反向代理。配置、连接和认证失败均以不含 token 的可观察错误显示。

### 快照合同

所有响应 JSON，带 `Cache-Control: no-store`；服务运行时读取状态，非 2xx 不被当作成功快照。

- `GET /v1/status`：返回协议版本、服务 PID、当前 Bot UID、owner UID、运行中会话数量、排队任务数量与采样时间。计数与现有运行状态和持久队列来源一致；计数口径以进程当前视图为准，恢复中的状态不伪报为已完成。
- `GET /v1/chats/status?channelType=<type>&channelId=<id>`：返回协议版本、请求的精确聊天身份、采样时间、该聊天的执行状态、下一次启动使用的模型策略、绑定工作目录、排队任务数与待回答问题数量。`channelType` 只接受 1、2 或 5；没有绑定或任务时用明确的 `none`/`null` 表达；无效参数返回 400。状态使用当前持久绑定和任务数据，不声称模型一定是运行中 worker 的实际模型。
- `GET /v1/chats/details?channelType=<type>&channelId=<id>`：同样认证并精确按 bot 和聊天隔离，返回 `version`、`sampledAt`、`channelType`、`channelId`、`context`、`references`、`tasks`。`context` 包含 `source`（`live|persisted|unavailable`）、`stale`、`usedTokens`、`contextWindow`、`percent`、`model`、`observedAt`、`note`；数据不可用时数值为 null。实时读取仅查询当前绑定的活动 worker，不启动 worker 或写入快照；无活动 worker 时读身份匹配的持久快照并标识历史数据。`references` 是 `{pr: string[], mr: string[]}`，仅返回当前线程已确认的关联。`tasks` 是当前线程已绑定的 Loop Task，元素包含 `workspaceId`、`taskId`、`title`、`status`、`url`；缺少快照或可靠链接时对应字段为 null，不猜测链接。非线程返回空关联；不返回上下文正文、任务描述或其他聊天的数据。
- 成功响应字段：`version` 为整数 `1`；`sampledAt` 为 UTC ISO 8601 字符串；`pid`、`runningSessions`、`queuedTasks`、`pendingQuestions` 均为非负整数。服务快照包含 `version`、`sampledAt`、`pid`、`botUid`、`ownerUid`、`runningSessions`、`queuedTasks`；两种 UID 为字符串或 null。聊天快照包含 `version`、`sampledAt`、`channelType`（整数）、`channelId`（字符串）、`state`、`model`、`cwd`、`queuedTasks` 和 `pendingQuestions`。`state` 为 `none | idle | queued | running | completed | failed | cancelled | interrupted`，`model` 与 `cwd` 是字符串或 null。`model` 是下一 worker 的显式或父线程策略，null 表示交由 OMP 决定。错误响应形如 `{"error":{"code":"invalid_request"}}`，状态码为 400、401、404、405 或 500；不返回内部异常内容。新增字段不得改变既有字段语义。不返回所有聊天列表、会话正文、问答内容、原始日志或凭据。
- 客户端按页面提供的当前聊天身份请求状态，并核对响应身份与发起请求时的身份；聊天已切换、页面重建或请求过期时丢弃响应。持有 token 即可查询任意知道身份的聊天，因此 token 是该 channel 状态的完整读取权限。

## 客户端与面板

面板由增强器本地插件在明确允许的 OctoBuddy 页面创建，使用现有宿主桥接与严格目标匹配。入口默认位于页面右边缘中部，半透明显示，鼠标悬停时不透明；可拖拽至页面内其他位置，点击展开或收起，页面重载后恢复默认位置。展开面板约 420px 宽，受窗口尺寸约束，内容可滚动；包含「状态」「上下文」「关联」三个 Tab，分别展示现有服务/聊天状态、当前会话上下文用量、当前线程 PR/MR 和 Loop Task。可用链接可打开；无数据、过期和失败状态明确显示。切换聊天立即清除旧数据，不累计面板或定时器。

服务与聊天状态定时刷新；同一面板只保留一组刷新任务，同一快照流串行请求，或以递增请求代次丢弃已被更新请求取代的响应，避免同一聊天旧响应覆盖新状态。检测到聊天切换时立即清除旧聊天的展示和在途请求，再查询新目标；无法准确识别时显示「无法识别当前聊天」，只保留服务整体状态，不猜测或沿用上一个聊天。服务无法连接或认证失败时区分显示；可以展示上次成功快照，但须清楚标记为过期并显示成功时间，不能标成在线或实时。token 或 base URL 未配置时显示未配置，不进行请求。

真实 OctoBuddy 的聊天身份来源须在隔离实例和可访问的真实页面上验证；用户信任本地页面与插件，页面脚本能够影响页面提供的聊天身份。测试中的合成身份不能替代真实页面验收。

## 失败与生命周期

- 服务端启动失败如实报告；已有 channel 的任务与消息处理不因一个状态请求失败而改变。服务关闭时停止接收请求并关闭监听器；重启后客户端重新连接。
- 设置有限的请求期限和响应大小，防止失联阻塞面板；错误信息不包含凭据或原始响应体。网络、认证与协议错误分别可观察。
- 请求快照与正在变化的任务状态可能存在采样时差；采样时间代表读取时刻，不承诺跨字段事务级实时一致性。没有实时 worker 模型时不推断其值。
- 单个授权 token 是只读权限边界；失窃或更换后旧 token 不再有效。部署者负责所选网络的访问控制、传输加密和主机凭据安全。

## 验收标准

1. **远程查询与默认配置（需求 2、3、5、8–11）**：配置环境变量 token 时默认启动监听，不创建配置或 token 文件；缺少 token 时 channel 继续运行，接口不启动并提示；已有私有 token 文件可回退。环境变量逐字段覆盖文件配置和默认值，显式关闭时无监听。隔离两端通过真实 HTTP 验证正确 token 获得快照，缺失/错误 token 为 401，非 GET 被拒绝，无跨源授权、无重定向跟随、无 token 泄露；不安全的凭据文件权限拒绝启用或连接。使用不同 base URL 均走相同客户端逻辑。
2. **只读与身份（需求 1、6）**：真实服务状态和聊天任务变化反映在 API；查询前后绑定、任务和数据库状态不发生查询引起的变更，且不创建 worker；不同聊天、线程和 bot 不串状态，未知目标返回明确空状态。
3. **面板（需求 1）**：真实 OctoBuddy 页面展示、收起和恢复面板；刷新、重载、窗口重建、插件禁用及切换聊天不重复、不显示旧聊天数据；同一聊天的乱序响应不覆盖较新的快照；缺配置、认证失败、离线、过期和恢复各有正确状态。
4. **身份与链路实证（需求 1–3）**：隔离测试不得以人工 DOM 身份替代真实聊天身份验收。经用户授权后，在客户端与 `my-mini` 真实 Tailscale 环境验证服务启动、认证查询、聊天切换和断线恢复；若不能验证真实身份，明确记录该限制，不宣称该部分可用。验证不得提交业务任务或重启现有服务。
5. **兼容性**：增强器既有 Zed 插件和管理快捷键继续工作；未启用状态接口时 channel 生命周期与原有行为一致。服务关闭与重启路径以及真实 HTTP 边界由隔离 fixture 覆盖。
6. **多 Tab（需求 14–17）**：真实面板显示三个可切换 Tab 和较大的响应式窗口；上下文展示准确的实时或历史用量，不暴露会话正文；关联仅展示当前线程确认的 PR/MR 和绑定的 Loop Task，可用链接可打开。切换聊天、关闭面板和服务离线时不显示其他聊天的旧数据；查询不创建 worker 或写入业务状态。

## 隔离验收记录

- 状态接口、私有凭据、只读快照和真实 CLI fixture 的针对性测试通过；安装的 OMP 离线重启基准覆盖正常退出和 SIGKILL。
- 使用已安装的 OctoBuddy 和临时未登录资料，验证真实通信页面中的面板展示、收起、禁用及重新启用；向该页面真实共享实例赋入受控群、子区及空目标，验证观察器和面板切换。这不等同于真实登录聊天验收。
- 客户端通过 `http://my-mini:<临时端口>` 连接远端隔离服务，验证服务与聊天快照、未认证 401，以及服务停止后的离线快照；远端业务服务未修改。
- 环境变量配置的隔离 CLI、增强器启动链和私有 `.envrc` 测试通过；使用环境 token 的远端临时服务通过 `my-mini` 返回服务及聊天状态、拒绝未认证请求，并在关闭后显示离线缓存。
- 多 Tab 验证：隔离真实 CLI 的详情接口、上下文快照与关联隔离、宿主桥接取消及浏览器中的响应式面板测试通过；已安装的 OctoBuddy 使用临时未登录资料和本地 HTTP fixture 展示并切换三个 Tab，真实聊天身份与部署后的远程详情仍需现场验证。
- 当前部署只读探测：已配置的客户端访问 `/v1/status` 返回 200，`/v1/chats/details` 返回 404；已登录 OctoBuddy 显示的是原单页面板。未重启服务或重载用户应用。
