# 会话压缩生命周期设计

## 目标与范围

手动和自动压缩向所属聊天发送真实开始及终态提示。压缩继续由原生 OMP 执行；Channel 保持任务普通输出、错误、取消、会话上下文与归档顺序，不改变压缩策略或模型选择。

## 实现

匹配当前 session 的压缩 start 产生开始提示；匹配终态根据原生结果提示完成、失败或取消，重复事件不重复投递。只有成功结果可报告完成；跳过、重试或缺少结果不代表成功。提示采用固定安全文本，不透传摘要或供应商错误。手动 `/compact` 可能先返回本地 ACK、随后才开始或结束：worker 必须继续持有该任务，直到匹配的原生手动压缩结束，或在无 start 时观察到已核实的本地终态输出、取消或停止。原始命令输出不透传；一般任务错误处理保持不变。非绑定 session 的事件不能影响当前命令或聊天提示。上下文刷新必须由原生已提交的 compaction entry 支持，不以通知或单纯命令输出推测提交。

## 验收

隔离 RPC 子进程覆盖自动方法切换成功、失败、取消、跳过、重复事件及独立后续轮次；手动模式、无 start 终态、取消和停止。验证提示与真实生命周期一致、无原始摘要或错误详情泄露，其他通知与正文仍正常投递，手动 ACK 不提前释放 worker。使用真实安装 OMP、隔离 session、有限 localhost 模型和本地 Octo 夹具验证手动及自动压缩通知、提交顺序和正常输出；不调用真实模型或修改业务状态。

2026-11-11 隔离验收使用已安装 OMP 18.18.8、有限本地模型和加密 Octo 夹具：手动与自动 remote 压缩各提交一条原生记录；扣住终态帧时已收到开始提示且没有完成提示，放行后各收到一次完成提示。会话绑定保持不变，摘要未进入聊天。自动场景还观察到一次原生跳过。验收未连接真实模型或常驻 Bot。
