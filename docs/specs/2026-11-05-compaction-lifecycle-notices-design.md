# 会话压缩生命周期设计

## 目标与范围

手动和自动压缩不向聊天发送生命周期通知。压缩继续由原生 OMP 执行；Channel 保持任务普通输出、错误、取消、会话上下文与归档顺序，不改变压缩策略或模型选择。

## 实现

自动压缩的 start/end 事件不投影为聊天消息。手动 `/compact` 可能先返回本地 ACK、随后才开始或结束：worker 必须继续持有该任务，直到匹配的原生手动压缩结束，或在无 start 时观察到已核实的本地终态输出、取消或停止。原始命令输出不透传；一般任务错误处理保持不变。非绑定 session 的手动事件不能结束当前命令。上下文刷新必须由原生已提交的 compaction entry 支持，不以通知或单纯命令输出推测提交。

## 验收

隔离 RPC 子进程覆盖自动方法切换成功、失败、取消、跳过及独立后续轮次；手动模式、无 start 终态、取消和停止。验证压缩事件不产生通知，其他通知与正文仍正常投递，手动 ACK 不提前释放 worker。使用真实安装 OMP、隔离 session、有限 localhost 模型和本地 Octo 夹具验证手动及自动压缩提交和正常输出；不调用真实模型或修改业务状态。
