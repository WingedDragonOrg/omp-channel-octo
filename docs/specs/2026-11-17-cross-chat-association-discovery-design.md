# 同一 Bot 跨群事项关联发现

日期：2026-11-17  
状态：已实现；隔离验收与全量测试通过。

## 用户原始需求

1. 「目标：使用 spec-design 与 owner 讨论设计，让有权限的任意 agent 能发现某事项相关的 Octo 群/子区，从而了解设计、任务与进度。

范围：调查当前群组及消息搜索、worktree/projects、Loop task、PR/MR 等关联字段的现有读面和跨群访问边界；讨论需要增加什么工具或查询能力、search 与 list（包括分页）的适用性、采用 host tool 还是 octo-cli/oco CLI，以及 decision 模型是否适合 rerank 或其他作用。比较实际可行方案及成本、权限、结果完整性与证据来源。

约束：这是设计讨论，先使用 spec-design 收敛产品契约并与 owner 确认；不自行实施。不要绕过 bot 实际授权；区分明确绑定与搜索推断，避免将无结果等同无关联。既有子区关联和其他 channel 本地数据的可访问范围须以实际实现为证。

验收：在子区与 owner 确认查询入口、检索/分页、模型角色及失败处理等关键设计立场；形成可实施的规格，说明权限、关联证据和结果边界。原始需求：‘spec-design 讨论设计，加什么工具，是通过 search 还是 list(分页?) 使用 tool 还是 oco cli? decision 模型在里面是不是可以做 rerank？或者？’」
2. 「一个bot/octo 身份本身有且只允许绑定在一个 channel 实例，完全不可能需要进行跨 channel 关联，每个身份只负责自己范围内的事情」——明确实例和身份边界。
3. 「1. 允许，按 bot 对目标的实际权限过滤（推荐），但需要注意下，现在按照的 bot token?还是 bot id? (bot id 是稳定的，bot token 是会变的)」——确认同一身份内跨群访问及稳定身份要求。
4. 对「这里的『任意 agent』是否包含不由该 channel 启动的外部 agent？」选择「2」：仅 channel 启动的 agent；替代条目 1 中外部 agent 的可能理解。
5. 「默认使用 Decisions 排序 + 过滤，如果没配置 decisions 进行静默回退」——确认模型作用和未配置时的行为。
6. 对模型判为不相关候选的呈现选择「1」：默认过滤，但可查看被过滤候选；明确绑定保留，模型失败保留候选并标明未完成。
7. 对完整设计摘要选择「1」：确认形成规格，包括本实例只读宿主工具、权限、来源、分页和失败处理；不授权实施。

## 目标与范围

让 channel 启动的 agent 从事项描述或已知身份出发，发现**同一 bot 实际有权访问**的 Octo 群及子区，并取得可追溯关联证据与进一步了解设计、任务、进度的读取入口。关联不要求使用 Loop：群/子区、工作区和 PR/MR 也可作为线索。

只读查询，不创建或修改关联，不派发任务，不读取其他 bot 或其他 channel 实例的本地状态，不为外部 agent 提供接口。一个 bot/Octo 身份只绑定一个 channel 实例；本设计不引入跨实例注册、同步或信任机制。允许 agent 后续按现有权限使用 `octo-cli` 读取发现目标的说明、消息及 Loop 任务；发现不代表获得写权限或执行权限。

## 现有事实与方案选择

- `src/host-tools.ts` 的 `octo_management` 从调用聊天确定当前父群；`list-threads` 和 `thread-info` 只能操作该父群。前者最多返回 50 条宿主投影，底层现有 transport 的无分页线程列表最多首 100 条；`thread-info` 拼接本实例的 workspace、Loop 路由和 PR/MR 引用。
- `thread_workspaces`、`loop_task_routes`、`thread_references` 等本地记录按 `bot_uid` 与对应群或子区身份存储。PR/MR 引用经当前子区 Decisions 判断后记录规范 URL；现有记录不保存原始消息、判定概率或证据摘录。它是 channel 记录的模型识别引用，不是人工确认的绑定。Loop 路由是明确关联；workspace 记录证明资源归属，不单独证明业务事项相同。
- `octo-cli group list` 列 bot 所在群，当前 CLI 未提供群名搜索分页。`thread list` 按父群分页，显式分页时上限 100 条；不传分页参数只取最多 100 条。`message search groups` 返回关键词匹配聊天聚合，不提供游标，聚合计数可能近似；消息详情搜索支持游标。搜索结果并非全量聊天或说明索引。Loop task search/list 按 workspace、页码查询；task 的 PR 列表是单独读面。具体可访问性由服务端和部署决定。
- 服务端源码核实：子区读取以父群有效成员资格及子区未删除为准；`GET /v1/bot/groups/{group}/threads/{short}` 执行这一检查，允许读取已归档子区。群详情只检查未删除成员，不能证明有效成员；群下子区列表接口执行有效成员校验，但只列活动子区。消息搜索聚合还受每群及单次子区枚举上限约束，覆盖不可视为完整。
- 状态 HTTP 的单个 Bearer token 可查询本实例已知聊天 ID 的状态与关联，不校验目标聊天的 Octo 权限；它不能直接作为此功能的授权边界。`octo_management` 的范围也不等同 Octo 的跨群权限；worker 另可用本 bot 的 `octo-cli` 凭据访问服务器授权的 API。
- `src/runtime/octo-cli.ts` 以 bot UID 选择独立凭据目录，登录时校验返回的 robot ID；token 是当前调用的凭据，不是持久归属键。已有 Decisions 授权限于当前子区的有界上下文，本设计明确扩展为已通过目标权限检查的跨群候选必要内容。

| 路线 | 成本与边界 | 决策 |
| --- | --- | --- |
| 仅 `octo-cli` 远端搜索和列表 | 已有 API，任何候选需 agent 自行组合；不暴露 channel 本地的 task 路由、workspace 和 PR/MR 引用 | 保留为远端读取能力，单独使用不能满足目标 |
| channel 只读 host tool 聚合本地与授权远端读面 | 可绑定 worker 的 bot UID，统一来源、预算和模型处理；需要新增宿主查询、权限检查和分页状态 | 采用 |
| `oco` CLI 或状态 HTTP 对外暴露本地索引 | 要新增外部调用者认证及跨机器信任，现有状态 token 不提供逐群授权 | 不在范围内 |

## 查询契约

新增只读 discovery host tool，向 channel 启动的各聊天任务提供，包括私聊、群和子区。调用绑定任务所属的真实 bot；不接受 bot UID、token、任意身份或其他实例作为选择器。支持首次查询和后续分页：

- 首次查询可提供事项描述/关键词，和可选的结构化线索：Loop workspace ID 与 task ID、PR/MR URL、项目仓库 URL 或本地工作区路径。至少提供一条线索。结构化值按其来源的规范形式精确匹配，不以名称相似伪造身份；task ID 与 workspace ID 成对定位，避免跨 workspace 混淆。对没有对应结构化线索的来源使用明确的事项文本查询，而不把 URL 或路径变成无约束全库枚举。
- 首次查询返回查询 ID、正常候选的第一页、被模型过滤候选的数量及其独立分页入口、各来源覆盖状态和正常候选续页入口。每个候选有真实 `channelType`、`channelId`、父群及子区身份（适用时）、可显示的名称、证据列表、来源采样时间，以及可用的进一步读取入口；不得猜造 URL、名称、任务状态或时间。
- 证据类别至少区分 `loop_route`（明确 task—子区路由）、`recorded_reference`（本实例记录的 PR/MR 引用，标识其模型识别性质）、`workspace`（本实例记录的项目/路径/仓库线索）及 `message_match`（远端搜索命中）。候选可有多条证据。每条带真实来源及可用的 task、URL、项目记录或消息身份；不存在的原始消息、证据摘录及模型置信度均不补造。workspace 和文本命中只作为相关线索。
- 按真实聊天身份去重并汇总证据，不因为同名合并不同群或子区。同一事项可能对应多个群和子区。Loop 关联查询合并 `loop_task_routes` 和 `loop_route_endings` 的已知记录，按 bot、群、workspace、task、线程及 route version 关联；保留当前路由及 ending 的 `pending|ended`、`reason`、`updated_at`，不能将结束记录说成正在执行或把不同版本的线程混成一条。归档或已结束路由如仍有持久关联，可以作为历史关联返回。
- 页内输出有确定顺序；模型排序可改变推断候选顺序，明确 task 路由和已记录引用始终保留，不因模型判断丢弃。每页含一个正常或被过滤候选集合；续页不得把两集合混淆。

## 授权与身份

- 持久关联始终按 channel 当前经注册确认的稳定 bot UID 查询，绝不使用 token 内容或 token 哈希作为持久身份。更换同一 bot 的 token 不改变已记录关联；当前 token 必须有效并由 Octo/Fleet 服务鉴权，bot UID 本身不授予读权限。
- 对每个候选，无论来自本地记录、远端搜索或列表，在返回任何目标身份、名称、关联、路径或证据以及发送模型前，使用当前 bot 对该目标相应 Octo 读接口做权限核验。搜索、列表命中和原始消息只能发现候选，不能单独证明目标当前可读。群和子区按其真实身份验证；不得只凭历史 membership、本地 `allowed_chats`、当前群或 HTTP 状态 token 推断权限。实现时核实实际接口对目标子区的访问校验；若该接口只能证明父群成员身份而不能证明子区读取权限，则还需能证明目标读取权限的接口；不能证明即不返回该目标。
- Loop 任务及关联证据（包括 workspace ID、task ID、标题、状态和路由）须同时通过目标 Octo 读取权限与当前 bot 的 Fleet/Loop workspace 读权限核验；不可读时不返回或发送模型，也不从本地路由泄露这些字段。已确认 Octo 目标可见不能替代 Loop workspace 授权；以其他已授权来源发现的同一聊天仍可返回其他证据。拒绝、鉴权故障和无法核实不能转为成功的空查询，也不能借用不同凭据、用户身份或 OBO 绕过。
- 内部可用来源级错误报告不完整；对未经授权或未核实的具体目标不泄露其身份、数量或本地关联。若 API 为保护存在性而静默过滤，报告该来源受其可见范围限制，不声称覆盖被隐藏对象。
- 每次继续分页时重新检查将要返回的目标及其各证据所需的 Octo、Loop 权限，且只输出当前仍可读的证据；目标已失权或无法验证时从页结果排除，Loop 失权时移除对应证据，并使覆盖状态反映权限变化或校验失败，不泄露目标或受限证据。返回的过滤数量须重新按当前授权计算，无法核实时标为未知，不暴露失权对象数量。查询缓存绑定原 bot、发起任务和查询 ID，不能跨 bot、跨任务读取；任务终态、查询 TTL 到期或服务重启释放缓存，之后旧查询 ID 明确失效。单次分页调用取消不删除仍在运行的任务拥有的查询；取消首次查询则不发布查询快照。不持久保存正文或重放查询。

## 检索、预算与分页

1. 结构化输入优先查询本 bot 的本地 Loop 路由、工作区归属与 PR/MR 引用，按真实字段匹配并保留记录状态。对 workspace、PR/MR URL 和 Loop task 的检索增加必要的只读索引或查询，不改变写入契约。
2. 远端消息搜索聚合发现匹配聊天，再根据需要分页获取有身份的消息命中；聚合没有游标，覆盖标为未知。群的枚举范围为当前 bot 的 group list 返回集合；若服务不能证明群列表完整，覆盖标为未知。对枚举的目标群通过远端线程分页接口逐群读取，记录各群耗尽或截断状态，不用当前宿主 `list-threads` 的前 50 条或 transport 首 100 条充当全量列表。Loop workspace 范围优先取 Fleet 授权的 workspace list；若无法枚举，只能查询用户提供的 workspace 和本实例已知绑定，并标记范围受限。逐 workspace 分页查询任务，任务与聊天的直接关联只由本地记录或来源明确的远端关联支持，不能凭标题相似升级。群名和说明仅作为线索，不证明事项关系。
3. 来源各自具有独立的查询/分页预算、已完成或截断状态和后续游标/页号；完成由真实服务返回的分页契约决定。首次采集过程中的数据变化不承诺跨来源或跨远端页一致快照。来源失败、取消、速率限制和预算耗尽按来源报告，已成功结果保留；取消不继续执行后台查询。
4. 首次查询结束时冻结本次已采集、已授权候选的身份、去重证据、模型分类和顺序，形成有界短期快照；后续页仅重验权限并移除失权目标或字段，绝不重查来源、追加候选或重新分类。来源截断时可用响应所给的来源续查位置发起新的首次查询，带原查询条件和来源范围，产生新的查询 ID，不能将新数据混入旧快照；不支持续查的来源明确标记。续页使用不透明的查询 ID 和位置，正常与过滤集合分别分页。
5. 固定默认预算：每页最多 20 个候选；每个来源最多 10 次远端请求、单次查询总采集最多 200 个候选；模型最多处理 100 个候选，每个候选最多 1,000 个 Unicode 字符的必要证据，模型请求预算 30 秒。单查询快照最多 2 MiB，TTL 5 分钟；每任务最多 4 个活动查询、每 bot 最多 32 个。达到任何上限时标明对应来源或模型的部分覆盖，未进入模型的候选保留；超出快照容量则明确返回容量错误，不发布不完整且未标记的快照。各预算在工具描述中公开，不增加 operator 配置项；测试覆盖每项上限、过期和任务终态释放。
6. 全局搜索、远端列表和本地记录都可能遗漏。返回来源状态、已请求范围、采样时间、来源分页是否耗尽、被过滤/截断情况；无命中只能解释为已查可见范围内无命中，绝不声明不存在关联。已获取但未继续的来源须报告部分结果。

## Decisions 排序与过滤

当 `decisions.enabled` 且配置可用时，默认对**权限核验成功后**的有界推断候选排序、过滤；复用既有 Decisions protocol、endpoint、model 和 key。只发送查询意图及做判断必要的有界候选文本与身份线索；不发送 token、完整历史、系统指令、工具输出或未经目标权限校验的内容。文本是数据而非模型指令；输出必须引用本批真实候选身份，未知或重复身份及格式错误不能产生新候选或删除明确关联。

模型可将推断候选分为显示和过滤，并给出排序；所有模型过滤结果保留在本次查询的独立分页集合。明确 Loop 路由和已记录 PR/MR 引用总是保留；同时拥有明确证据和推断证据的候选也总是保留。若模型只评估预算内的部分候选，其他候选保留，并报告模型覆盖范围；模型不得对未评估候选作隐式过滤。不能把概率称作关联事实，也不能把过滤结果解释为不存在关联。

未配置 Decisions 时静默回退确定性排序，保留全部已授权候选；无需给聊天增加提示。已配置但请求失败、超时、拒绝、结果不符合契约时，保留全部候选并在工具结果标识模型未完成。对过滤候选的计数只包含已核验且模型处理成功的本次候选，不泄露未授权目标。

模型的排序及过滤质量、真实延迟和费用尚无本任务实测；实施时使用授权的标注样本测量召回、误过滤率、延迟和成本。采样不以真实生产聊天内容外发为前提；真实 provider 试验及外部数据使用仍须符合现有部署授权。

## 失败和观察

- Octo/Fleet 认证、权限、网络、协议、分页和配额错误按来源区分，既不静默换凭据，也不把失败当无关联。服务端不揭示目标存在时不自行区分不存在与无权。
- 目标或 Loop 的访问权在查询中变化时，以返回时有效权限为准；查询不是长期授权凭据。针对已发送到模型的内容，后续权限撤销不能撤回已发送数据，因此只在发送前验证并限制内容。
- 本地记录可能过期、远端线程已删除、创建状态未知、模型识别错误或来源未覆盖；返回记录自身状态和证据，不把它们升级成实时工作进度。没有 source message 的旧记录不生成伪来源。
- 同一仓库可服务多个事项；同一事项可跨多个仓库、群及子区；不按 cwd、worktree 名或 URL 子串建立隐式确定性绑定。

## 验收标准

1. **入口和身份（需求 1–4、7）**：真实 channel worker 可调用只读工具，不能选择其他 bot 或实例；不同 bot 的本地数据隔离。同一 bot token 轮换后旧关联仍可发现，远端使用新有效 token；外部 agent 不获得新接口。
2. **授权（需求 2、3、7）**：两个群分别可读、不可读和撤权；本地残存记录不绕过实时权限；子区和 Loop workspace 权限各自验证，无法证明时不泄露目标；续页撤权生效，权限、网络、身份错误不变成无关联。无需真实生产资源。
3. **证据（需求 1、7）**：Loop 明确路由、模型记录的 PR/MR 引用、workspace 归属、消息搜索分别标识，多个来源合并到真实聊天身份；PR/MR 不伪造原文或概率；同仓库/相似标题不被当作明确业务绑定。agent 能据返回身份使用既有读面进一步了解设计和进度。
4. **分页与完整性（需求 1、7）**：模拟超过各来源一页、无分页搜索聚合、列表变动、上限、截断、部分失败和空结果；返回可继续页及可观察的来源覆盖，零命中不表示无关联。正常及模型过滤集合均可分页；跨 bot/任务的查询 ID 拒绝，过期与重启失效明确。
