# 子区工作区创建时同步项目代码

日期：2026-11-20

## 用户原始需求

> ## 目标
> 研究并设计 `/thread` 创建涉及的项目 worktree 前是否及如何同步最新代码，避免基于过旧代码而遗漏进度；同步冲突时仍使用原有代码创建 worktree，并通知用户手动同步。
>
> ## 范围
> 调查当前单仓、显式项目、多项目以及指定 base 的创建流程，确定“最新代码”的来源和同步范围、worktree 起点、冲突及通知行为。评估同步父仓或项目现有工作区对未提交改动、并行任务和 Git 状态的影响，以及同步失败、离线和无 upstream 等情况。
>
> ## 约束
> 该需求涉及工作区和现有代码的潜在变更，先使用 spec-design 形成方案，在子区以最少问题确认无法从现有约定推导的产品决策；不要擅自对真实仓库执行 pull、merge、rebase 或清理，不操作或重启常驻服务。明确保护已有进度与未提交更改，保留显式 base 语义、多项目一致性、失败结果和可靠通知。方案获确认后直接实现并验证。
>
> ## 验收标准
> 给出可验证的同步/回退和通知契约，覆盖成功同步、冲突时旧代码建 worktree 并通知人工同步、已有改动、指定 base、多项目与失败场景；在隔离 Git 仓库执行端到端验证，更新规格并报告结果。

用户确认：未指定 base 时固定当前 HEAD 和当前分支 upstream，获取远端提交并在新 worktree 内合并；冲突及离线等明确失败回退到原 HEAD 并通知人工同步。显式 base 不自动同步。保留源工作区和未提交内容；fetch 可更新远端跟踪引用及 FETCH_HEAD；逐项目报告，整个批次成功才 ready。取消或结果未知不伪称成功；采用现有持久投递并保留投递失败状态。

## 现状

无 projects 时来源为调用方 cwd 的 Git worktree；显式 projects 分别使用所指定的仓库检出。指定 base 先在源仓库验证为 commit，然后原样传给 wt 或 OMP。未指定 base 时当前创建链没有网络同步。项目逐一创建，shared/separate 批次要全部准备并持久提交成功才 ready；已有创建意图和资源归属承接部分与未知结果。

## 行为契约

- 无显式 base 的每个项目在同步前固定源检出的 HEAD 和当前分支所配置的 upstream，向该 upstream 的远端获取对应分支，不推送、不更改源检出或本地源分支。以固定 HEAD 创建新 worktree，在其中整合固定的已获取 upstream：可快进时快进，分叉时合并，保留双方已提交进度。源 worktree 的暂存、未暂存及未跟踪文件不修改，不保证复制进新 worktree。
- fetch 允许按 Git 配置更新远端跟踪引用和 FETCH_HEAD；并行 Git 操作可能变化，创建起点与合并目标使用已解析的 commit，不能把跨项目结果称为同一时刻的原子快照。
- Worktrunk 创建 hooks 依既有时序执行，可能先于新工作区的合并而看到原 HEAD；hook 或 clone-first 带入的文件属于新工作区现存内容，同步和失败回退不得擅自丢弃。
- 合并冲突、远端不可达、无 upstream、获取或明确的合并失败时，新 worktree 以固定的原 HEAD 保留；若合并已开始，先确认清除本次新 worktree 的合并状态。按项目说明失败原因、原始起点和工作区路径，提示人工同步；不把同步失败当作工作区创建失败。无法确认回退、进程退出或操作结果时不得宣称已回退或 ready，不自动重放不确定副作用。
- 同步结果尚未持久化时发生重启，启动恢复将该项目标记为结果未知、保持批次未就绪，并与创建方的核验提示在同一事务写入 outbox；重复恢复不重复发送，不重放 Git 操作。只有能够确定持久创建方的记录才生成通知。
- 显式 base 保持原有语义，不自动同步，仍执行现有的创建前校验。不同项目分别取得同步结果；整个创建批次仍须全部工作区、绑定和说明成功才 ready。创建本身失败及部分资源按现有持久归属、恢复和失败契约处理。
- 返回每个项目的同步状态、实际起点和路径，失败信息通过创建方可见的持久投递送出；离线和投递失败按现有 outbox 的有界重试与终态记录，不承诺永久必达或伪称送达。不得泄露凭证或原始 Git 诊断。
- 操作遵守现有取消和受管进程契约；新同步步骤不得造成源工作区清理、重置、stash、checkout 或 pull，也不得中断独立任务。

## 验收

在隔离真实 Git 仓库及本地远端覆盖：仅远端前进、源分支与远端分叉且可合并、冲突回退、离线和无 upstream、源工作区存在暂存与未暂存改动、显式 base、shared/separate 混合项目、创建失败与通知投递。检查实际提交、文件、源仓库状态及批次 ready 和用户通知；验证取消及结果未知不冒充成功。使用隔离 fixture，不操作或重启常驻服务。
