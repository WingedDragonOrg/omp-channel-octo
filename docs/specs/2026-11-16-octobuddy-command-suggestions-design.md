# OctoBuddy 输入框命令提示设计

日期：2026-11-16

## 用户原始需求

1. 「在输入框支持 / command 提醒」（附 OctoBuddy 聊天输入框截图）。
2. 对命令范围选择「2」：channel + OMP 命令。
3. 对建议的输入体验、目录来源、会话与身份、失败行为、边界和验收方案确认：「ok」。
4. 对无法预先确认交互能力的扩展命令选择「隐藏无法确认的扩展命令：避免推荐潜在不可用命令，但也会隐藏可正常执行的扩展。」——调整 OMP 目录的展示范围。

## 目标与范围

在 OctoBuddy Enhancer 的聊天输入框提供斜杠命令发现和补全，覆盖 channel 命令以及当前聊天可通过 channel 使用的 OMP 命令。提示只辅助编辑；选择候选不发送消息，也不改变现有命令的权限、路由与执行语义。

使用已有增强器插件宿主、当前聊天识别和经 Bearer token 认证的 channel HTTP 通道。保持 OctoBuddy 安装包和资料不变。不改变群聊的 mention 要求，不通过提示授予命令权限，不自动重启或部署现有服务。

## 交互

- 输入框中位于命令开头的 `/` 打开输入框上方的候选列表；继续输入按命令名、别名及已输入的子命令过滤。候选显示名称、简短说明和可用的参数提示；支持列表滚动。
- 方向键选择候选，鼠标、Tab 或 Enter 将候选补全到输入框并保留焦点；候选打开且有选中项时 Enter 只补全，不发送。Escape 关闭列表。列表关闭或没有可选项时，输入和发送保持 OctoBuddy 原有行为。
- 补全只替换正在编辑的命令片段，保留已有参数和其他草稿内容。子命令候选按相同规则继续补全；无子命令数据时保留参数提示，不臆造候选。
- 输入法组合期间不拦截用于选字的按键。普通文本、非命令位置的斜杠、关闭列表以及插件不可用时，原输入行为保持不变。
- 切换聊天、输入框销毁、页面重建或插件禁用时撤销旧列表及事件处理；重新进入可用聊天后恢复。提示在可识别的当前 Bot 私聊、已启用群聊和子区使用现有聊天身份，不猜测目标。

## 目录与路由

- channel 拥有其命令和用法的目录；命令名称与实际路由共用权威定义，说明、参数和子命令与实际行为一致。目录包含别名及其作用范围，不将不可用于当前聊天的 channel 命令作为可执行候选。
- OMP 通过其 RPC `get_available_commands` 获取命令元数据，并处理 `available_commands_update`。候选包括可展示命令的名称、来源、别名、说明、参数提示和子命令。必须在实际安装的 OMP 上验证该协议；不能取得目录时明确表示 OMP 命令不可用，不以静态猜测代替。
- 目录按当前 channel 路由合并：channel 内建命令及其别名优先于 OMP 同名项。OMP 不提供扩展命令的交互能力标记，因此隐藏 `source=extension` 的命令；项目文件命令及 skill 命令仍按当前目录展示。已知需要交互式终端且 channel 无法完成的子命令不列为候选。动态命令的可用性仍受运行时配置及权限约束。
- 运行中的精确聊天 worker 提供当前目录和更新。空闲时以该聊天实际工作目录及其生效的 OMP 配置启动隔离探测 worker，获取目录后关闭并完成进程清理；不打开、修改或占用当前持久会话，不调用模型、不提交 prompt、不发送消息。探测可加载项目扩展，遵守现有受管 worker 的进程、退出与关闭边界。探测中的聊天绑定或工作目录改变后，旧结果不能用于新绑定。
- HTTP 查询由 channel 服务拥有，使用现有认证和增强器宿主桥接；按 bot、channelType 和 channelId 精确查询，沿用 Bot 私聊的身份映射。只传递提示所需元数据，不传聊天正文、命令模板内容或凭据给页面。该只读目录能力不触发任务、变更绑定或执行命令。

## 状态与失败

当前聊天身份变化时立即清除旧候选并丢弃旧请求结果；同一聊天的目录更新与请求响应按代次处理，较旧结果不能覆盖较新结果。关闭页面或插件时释放订阅、请求和 UI。

服务不可连接、未配置、认证失败或 OMP 目录获取失败时，提示对应状态；可用的 channel 命令仍可显示，但不能把缺失的 OMP 部分表示为完整目录。不得复用其他聊天的旧目录。输入框始终保留原有编辑和发送能力。

空闲探测失败或无法确认退出时按现有 worker 生命周期如实处理，不因提示功能占用或破坏现有会话。HTTP 持有者可查询已知聊天的命令元数据，沿用现有状态接口的认证与网络安全边界。

## 验收标准

1. **输入与补全（需求 1、3）**：在真实 OctoBuddy 输入框输入 `/` 显示候选，输入前缀过滤；键盘、鼠标、子命令和参数提示可用；补全不发送，原有草稿及参数不丢失，IME 选字和普通输入不受影响。
2. **目录正确性（需求 2–4）**：channel 命令与实际路由一致；同名时 channel 优先。隔离真实 OMP RPC 验证目录及更新，覆盖项目命令、不同 cwd、扩展命令隐藏和不可用于 channel 的子命令；不以目录存在代替执行路径验证。
3. **聊天与生命周期（需求 2、3）**：群、子区、Bot 私聊按正确身份取目录；切换聊天、绑定变更和乱序响应不展示旧目标结果。运行中使用当前 worker，空闲探测不打开或修改持久会话；探测退出后受管进程已清理。
4. **失败与权限（需求 3）**：离线、认证失败、OMP 不支持目录或探测失败时状态清楚，仍可正常编辑和发送；不触发任务或模型请求，原有命令权限和 mention 门禁不变。
5. **增强器生命周期（需求 1、3）**：隔离 OctoBuddy 页面验证重载、窗口重建、聊天切换与插件禁用，不重复 UI 或监听器；实际登录聊天身份与真实输入框若无法验证，交付时明确说明，不以合成页面替代。

## 隔离验证记录

- 命令目录、权限、工作目录隔离、取消和 worker RPC 更新由针对性测试覆盖；运行中的聊天使用其现有 worker。真实安装的 OMP 通过本地 HTTP 查询，在两个临时项目中分别发现各自的项目命令，未修改原绑定或启动任务，探测进程退出后没有未终结的 worker ledger。
- 增强器的浏览器测试覆盖目录桥接、补全、草稿、mention、输入法、聊天切换和插件清理。安装的 OctoBuddy 使用临时未登录资料验证了通信渲染器的插件生命周期；该环境没有真实聊天输入框，因此未验证真实 ProseMirror 中的补全。
- 离线重启基准覆盖正常关闭与 SIGKILL，两种场景均无会话重叠或重复效果。
- OMP 命令元数据不标识扩展命令是否需要交互式 UI；目录隐藏 `source=extension`，包括可能不需要交互的扩展命令。
