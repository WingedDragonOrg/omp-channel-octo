# 成员信息读取重试设计

日期：2026-11-10

## 用户原始需求

> 目标：成员信息读取失败时重试，避免临时失败导致消息未并入当前回合。

## 事实与目标

steering 领取消息 claim 后，在串行交付链查询当前群或子区成员；读取、校验或快照暂存异常均进入同一失败分支，完成 claim 并提示未并入，不入队。现有读取只有一次请求、5 秒预算。该分支没有记录异常，截图和本机对应时段日志不足以区分网络、服务端、超时、数据格式或暂存失败，不能断言本次底层原因。邻近时段有其他网络操作超时，但不能据此认定因果。

## 设计

仅对群和子区成员 API 的瞬时读取失败重试；首次任务与 steering 共用读取路径。每次请求最多 15 秒，最多三次，间隔分别为 1 秒和 2 秒；保留服务停止及任务取消信号，等待期间可中断。仅网络错误、超时、5xx 和服务端 store_failed 属于瞬时失败；权限、其他 4xx、非法成员响应及上下文暂存错误不重试。每次请求独立截止，过期响应不发布快照。重试不覆盖说明读取、卡片或 worker steer，不对未知 steer 结果重放。

steering 保持原消息 claim 和原串行位置，成功读取后重新检查原运行回合、取消及交付门禁，再以原消息 ID 暂存快照并只交付一次。快照仍仅在对应消息被消费后进入历史；重试期间重复投递沿既有 claim 去重。回合在投递前已结束时释放 claim，沿原普通任务路径处理；用户取消与服务停止沿既有取消和恢复契约，不再继续重试。重试耗尽且原回合仍可接收时保持原失败回执、不转成排队任务；首次任务保持原启动失败回执。未经确认的原生接受不重放。

## 验收

- 群与子区成员请求临时失败后恢复：原输入只交付一次，消费后对应成员快照正确，重复投递不产生第二次交付。
- 三次失败后保持原失败提示和已有任务；权限和格式错误不重复请求；超时及失效响应不可发布。
- 请求及退避中取消、服务停止、原回合结束，以及并发重复投递均遵守原 claim、顺序和 session 合同。
- 定向运行上下文及 steering 回归，验证真实 HTTP 错误类型及取消路径。只使用隔离资源，不操作常驻服务。
