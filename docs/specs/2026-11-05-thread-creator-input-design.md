# 子区向创建方输入

日期：2026-11-05

## 目标

已授权的子区任务可以显式向该子区持久记录的创建方聊天发送文字输入，让创建方 Agent 可感知并处理；普通 Octo Bot 消息不具备这一语义。

## 契约

- 群和线程提供的 `octo_management` 新增 `thread-send-parent`，只允许在当前子区调用，接收非空、有界的 `text`，不接受目标参数。使用子区持久监听记录中的创建方；无记录的历史子区按现有规则以真实父群建立默认记录。禁止向自身发送。发送不受 `listen` 档位影响；该档位仍仅控制自动回传。
- 宿主在交付前验证当前 Bot、owner、来源和目标聊天权限以及来源到创建方的持久关系；交付前再次检查。输入带真实子区来源、显式业务正文和系统提示：不是用户消息、问答答案或新增授权。不得把来源文本伪装为 owner 指令。
- 输入不经过普通 Octo 消息回声或待答 ask 路由；固定作为创建方聊天的独立任务持久接受并排队，不并入运行回合。回执报告 `queued`；接受不意味着父区已处理，不承诺返回处理结果。接受状态未知时报告 `uncertain`，禁止盲目重复投递。
- 以当前 channel task ID 与原生 toolCallId 的组合作稳定操作身份；缺少工具调用身份时拒绝。重放同一工具调用不得重复输入，保留已确认结果。任务接受与去重使用既有 durable 机制；恢复不重放原 prompt，接受状态不明时不得创建第二个任务。
- 新建子区在远端分配前持久记录创建来源和意图；未知远端分配不猜测创建方或重复分配，已知失败不阻塞其他子区。旧有监听记录保留其创建方；创建意图或 fork 记录存在时须与监听记录一致。旧 fork intent 可从其持久 fork 来源恢复。创建关系与 Loop 任务后续改绑相互独立。
- 入队与此前已经受理的创建方入站工作按同一聊天顺序衔接。来源任务的停止意图、身份和关系在任务持久接受事务中复核；停止意图先提交时不接受。入队后的任务遵循现有普通任务的执行、取消和恢复合同。
- 输出包含可定位的发送身份与回执，不能将已排队称为已处理。可见聊天消息不作为接收或唤醒的证明。异常、取消、权限变化和关闭时不伪报成功。

## 验收

1. 来源子区向创建方发送文字，创建方获得独立任务；运行中也排队，不并入当前回合；来源与非授权语义出现在创建方实际 prompt。
2. `listen=off` 仍允许显式输入；群调用、自身目标、无效正文和未授权来源或目标拒绝。现有自动 listen 行为不变。
3. 创建方有待答 ask 时该输入不是答案；独立输入不会绕过 chat/session FIFO。
4. 同一调用重复和重启恢复不产生重复任务；接受结果不明保持不明并明确报告；跨 session、不同 toolCallId 的调用互不混淆。
5. 用临时状态、隔离本地 transport/worker 和真实 OMP RPC 路径验证，不发送真实 Octo 消息、不修改真实业务状态、不重启常驻服务。运行相关回归、typecheck 与离线 restart benchmark；SQLite 结构变化使用抛弃式副本经真实迁移演练。
