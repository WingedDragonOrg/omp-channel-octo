# 独立代码审查命令

日期：2026-11-04

## 目标与交互

宿主内置 owner-only `/review [审查重点]`。每次以新的 OMP session 和普通审查正文运行，不调用 OMP 原生 `/review`，不将命令或正文转发主 worker。无参数审查当前工作区各项目相对各自 HEAD 的已暂存、未暂存和未跟踪变更；参数是附加审查重点。shared 工作区审查其记录的全部项目，其他工作区审查当前绑定项目。每次审查独立，不自动带入之前的审查结果；需要复核时由用户在重点中明确说明。

同一聊天同时最多一个审查，重复请求返回忙碌提示。`/review stop` 只停止该聊天的审查，不取消主任务；其他控制和查询命令保持可响应。原绑定和主会话不被修改。权限、群/子区 allowlist、mention 和命令持久去重沿用现有入口。

## 审查输入与范围

输入包含必要的当前聊天背景、真实项目路径、各项目 HEAD 和明确变更范围、用户审查重点，以及结果结构。采集可核实的变更基线，区分暂存、未暂存和未跟踪文件；工作区可能同时被修改，审查应说明基线及变化或不能确认的范围，不能声称审查了未核实的内容。缺少项目或无法采集时明确失败或报告未覆盖部分，不猜测路径或基线。

采集按项目记录前后两次 HEAD 和完整变更证据的核验结果；即使两次一致，也不是原子快照。二进制内容、dirty 子模块、无法读取和超限部分列入未覆盖范围。单次 Git 输出及未跟踪证据各限 4 MiB，单个未跟踪文件限 2 MiB；Git 采集可取消并有 30 秒时限，退出前保留资源使用记录。识别出的敏感信息在正文、重点和背景中脱敏，并注明影响的审查范围。

参考本机 OMP reviewer 标准：只报告有证据、可行动的实际问题，包含严重性、精确文件和行号、触发条件及影响、修复建议；说明审查边界与未覆盖部分，不制造发现。默认只读，不自动修改文件、stage、commit、merge、push 或部署。该约束是审查指令，不改变 OMP 工具的宿主授权边界；不将凭据、主任务原始工具协议或无关聊天内容写入审查上下文。

## 生命周期与隔离

命令持久受理及启动交接后立即释放入站链；后台操作明确登记、可停止、关停可等待。受理与去重必须原子一致；重启先处理旧进程所有权，再处理已受理状态。未派发的工作可按持久状态恢复；派发意图与实际接受分开记录，接受不明确时 fail closed，不能重复发送原 prompt。用户停止和普通服务停机分别遵守现有停止及恢复语义。完成、失败、停止均回收临时会话、受管 worker/watchdog、会话租约及卡片队列；退出无法确认时按现有规则保留资源阻塞与台账。

审查使用独立 session，模型通过 `resolveChatModel` 遵循聊天显式模型、父群默认、OMP 默认的既有优先级。复用现有共享资源使用记录保护 commit、merge、remove，普通任务不按 cwd 互斥。项目路径通过当前绑定和已记录的 ready 工作区取得；缺失或不确定的工作区不回落到其他目录。审查上下文不得覆盖主 session 的 sidecar 或绑定。

审查使用独立任务身份和进度卡，工具/步骤事件与终态仅作用于自己的卡；文本结果走既有持久出站。卡片复用能力协商、wire envelope 限制、脱敏、发送编辑与失败降级；运行和终态应真实可观察，不显示虚构百分比。卡片与文本不得混入主任务的流或覆盖其卡片。服务关停等待审查操作和卡片出站的收尾。

## 验收

- 同消息重复投递仅受理一次，未授权请求不启动；主 worker 从未收到审查命令、审查正文或 steering。
- 主任务 held 时独立审查可完成，主任务继续；控制命令可处理，绑定与主 session 不变，输出和卡片独立。
- 临时真实 Git 覆盖已暂存、未暂存、未跟踪和 shared 多项目；以确定缺陷及真实 OMP、有限 localhost 模型和本地 Octo fixture 验证整条链路。模型夹具只证明协议与接线，不宣称真实模型质量。
- 覆盖运行、成功、失败、停止的独立卡片及降级；确认能力限制与真实渲染的适用验证。
- 覆盖并发、持久受理、停止、崩溃恢复、未确认进程和资源操作保护；运行相关 core/worker/card 测试、typecheck、全量测试及离线 restart benchmark。不注册或重启常驻 bot，不调用付费 provider，不提交、推送、合并或部署。
