# OCO 状态目录统一与迁移

日期：2026-11-12

## 用户原始需求

1. 「为什么 state 不放在 ~/.oco ? 非要单独一个目录？各种目录应该统一，统计下设计到的目录，需要统一一下，以及注意 migration」
2. 「ok，默认 ~/.oco/state 即可，不需要明确配置，我会删除这项，重启时应该支持自动迁移」
3. 「什么玩意？为啥要动这个？现在的 state 里面只有 sqlite 啊？为啥还要动 worktree 和 session?」补充迁移范围：保留已有工作区与会话。

## 目录

省略 `stateDir` 时使用 `~/.oco/state`，显式配置仍生效。配置、日志、会话和 Bot 凭据分别留在 `~/.oco/config`、`~/.oco/logs`、`~/.oco/sessions` 和 `~/.oco/octo-cli`。已有工作区和会话保持原位置、原身份与原有绑定。

## 自动迁移

省略 `stateDir` 的服务首次启动时，自动将旧标准状态目录的 SQLite 状态迁至 `~/.oco/state`，保留已提交的 WAL 数据、owner、绑定、任务、队列、outbox 和其他已有记录；不存在旧状态时创建新状态。显式配置 `stateDir` 不触发此自动迁移。现有会话文件、Git worktree、工作区目录及其持久路径均保持不变。

旧状态目录还可能包含服务运行期间生成的附件、spool、上下文 sidecar 和其他文件。迁移不得删除或移动这些已有文件、改变数据库中指向它们的路径或让它们失效；新文件由新状态目录产生。旧数据库和文件在迁移验证前保留。目标已存在且无法证明属于同一次迁移时不得覆盖或合并；中断后须能安全恢复，不得以空数据库冒充迁移成功。

迁移在打开目标数据库及注册 Bot 前完成。必须排除旧服务及其他迁移对源数据库的写入，确认遗留受管进程状态，无法确认时拒绝启动并报告。`check` 和 `launchd install` 不得在自动迁移前创建会造成目标冲突的状态目录。读取锁失败或持有者状态不明不能被当作锁空闲。

## 验收

- 省略 `stateDir` 默认使用 `~/.oco/state`；显式自定义目录保持原行为。
- 重启自动迁移旧 SQLite（含已提交 WAL），保留原有持久状态；现有 session、工作区及文件路径保持可用。
- 使用隔离 SQLite、文件与真实 Git worktree 夹具验证正常迁移、重复启动、目标冲突、迁移中断和未退出的旧进程；不注册真实 Bot、不重启或修改常驻服务。
