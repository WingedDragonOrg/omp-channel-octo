# `/context` 独立卡片设计

日期：2026-11-10

## 用户原始需求

1. 「目标：排查为什么 /context 的显示不再是独立卡片。范围：查看用户截图……截图显示排队执行 /context 后输出为普通消息，包含可见的 ANSI 样式序列和进度条字符。追踪实际命令输出与 Octo 展示路径，查明原因及是否发生回归。约束：以证据为准，保留现有命令和消息交付契约；如确认是缺陷，按项目规范生成 SDD 并修复，必要的产品决策在子区内向 owner 询问。验收标准：说明根因和验证证据；如实施修复，验证 /context 以独立卡片正确展示，且不泄露终端控制序列，并覆盖相关回归。」截图本机路径省略。
2. 投递方式确认：「只支持 card，不支持回退，发送失败明确文本提示失败即可，不需要所谓的充实」。本条明确 `/context` 卡片的失败语义。
3. 「独立卡片，不支持文本回退，失败明确文本提醒，不需要重试」。
4. 「优化下卡片美观度和排版」；参考本子区提供的原卡片截图。

## 事实与目标

OMP 18.18.6 的 RPC `/context` 返回包含 ANSI SGR 序列和字符进度条的 `command_output`。channel 将该帧投影为普通通知，控制字符过滤只删除 ESC 而留下参数，导致终端样式代码出现在聊天中。仓库中的 `/status` 有独立状态卡；未发现 `/context` 独立卡实现的历史证据。

## 设计

保持 `/context` 原生 prompt、排队、权限、session、任务与本地命令结算语义。仅该命令产生的原生 `command_output` 转为独立 `octo/v1` 卡，不进入普通通知或进度卡；其他通知与原生命令保持原有投递方式。卡片展示 OMP 提供的上下文窗口、比例和逐项 token 数，删除完整终端控制序列和字符进度条，不伪造数值。保留无法解析的非控制文本，以免丢失上游输出。

卡片将原生已用比例作为主指标，窗口容量紧随其后；明细区逐项展示原生类别、百分比和 token 数。保留原生未识别的文本，不推算或改写占用数值。仅使用 `TextBlock`，保持既有能力门禁。

卡片复用既有能力检查与单次发送。服务端不支持卡片、发送失败或无确认时，使用既有文本出站发送明确的失败提示，不发送原生输出文本或伪装成成功；不重发未知结果的卡片。取消和停机遵循现有任务边界，不改变其他消息投递。卡片不是 assistant 生成内容，不写入任务结果。

## 验收

- 真实安装 OMP 的 RPC `/context` 输出经过实际卡片构造器和 Octo 客户端展示；模拟帧覆盖服务的命令投递路径。卡片显示原生数值，不出现 ANSI 序列或字符进度条。
- 排队命令按原有顺序执行；卡片不与进度卡或普通消息合并，不形成 assistant 结果。
- 卡片不可用或发送失败时只给出明确失败提示；其他命令、通知及文本投递不受影响。
- 定向测试覆盖终端序列、卡片投递、失败、队列和非 `/context` 事件；仅使用隔离资源验证。

## 验证证据

- 隔离 OMP 18.18.6 原生 RPC `/context` 返回 `command_output` 和 `agentInvoked:false`，原始文本包含 ANSI SGR 与方块进度条。
- 原生输出经过实际卡片构造器后，通过 Octo CLI 以当前 Bot 向本子区发送带「验证示例（隔离 OMP 会话）」标记的卡片，消息 ID `2120099580962836480`。Octo Web 实际页面显示窗口、各项比例及 token 数，未显示终端控制序列和方块进度条；数据来自隔离会话。
- `tests/core-presentation.test.ts` 与 `tests/omp-worker.test.ts` 共 129 项通过，覆盖排队、独立卡、能力不可用、发送失败不重试、通知和 RPC；`bun run typecheck` 通过。
